# 端侧部署方案

## 部署目标

最终设备在无网络连接时完成摄像头采集、图像预处理、模型推理、时序滤波、事件生成和性能记录。网络只能用于开发阶段的数据传输或软件更新，不能成为运行前提。

## 模型发布层级

每个任务建议保留以下产物：

1. 训练框架检查点，用于继续训练和复现实验。
2. 浮点导出模型，用于验证导出一致性。
3. INT8 模型，用于 CPU 或通用端侧运行时。
4. 设备专用模型，可选，例如 NPU 编译产物。

所有模型必须关联模型卡、输入输出定义、数据版本、量化校准集、文件哈希和评测结果。

## 轻量化策略

- 使用较小输入尺寸和眼部、手部 ROI，避免整帧高分辨率推理。
- 使用轻量骨干、深度可分离卷积或小型关键点回归头。
- 先做结构缩小和蒸馏，再做量化；避免只依赖压缩文件大小。
- 使用代表性校准集完成全整数量化，并单独检查困难场景精度下降。
- 检测器低频运行，跟踪器高频运行；置信度下降时才重新检测。
- 根据待机、跟踪和交互状态动态调整帧率和推理频率。

## 运行时约束

- 使用容量为一或很小的最新帧队列，过期帧直接丢弃。
- 每个阶段记录开始和结束时间，能定位采集、预处理、推理和后处理耗时。
- CPU 和 NPU 后端输出必须使用相同的数据结构和坐标约定。
- 模型与配置放在只读发布目录；用户数据和日志放在独立可清理目录。
- 发布包包含所有动态库和模型，不依赖首次启动联网安装。

## 设备配置档

### 开发机

- 运行教师模型和训练流程。
- 支持录制回放、可视化和详细调试。
- 不作为端侧性能结论的依据。

### ARM CPU 基线

- 验证完全离线运行和通用兼容性。
- 作为 NPU 加速效果的对照组。
- 必要时降低输入尺寸和活动帧率。

### ARM 加 NPU

- 运行 INT8 或设备专用模型。
- CPU 保留采集、ROI、状态机和日志职责。
- 需要记录编译器版本、算子回退和数据搬运开销。

## 发布检查清单

- 飞行模式或断开网络后可冷启动。
- 模型文件哈希校验通过。
- 相机缺失、模型损坏和 NPU 不可用时有明确错误或降级路径。
- 连续运行期间内存稳定，队列无持续增长。
- 日志中不保存不必要的原始眼部或面部图像。
- 版本信息能够对应到唯一训练运行和评测报告。
